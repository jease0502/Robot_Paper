# data/ — every number in the paper, and the code that produced it

This directory makes the manuscript reproducible on its own. Nothing here is
regenerated by `build_page.py`; it is the archive the figures and tables were
computed from.

```
data/
  scripts/    the experiment code, one file per experiment
  results/    the numeric output behind every table and figure
  rollouts/   the seven reward-ablation rollouts, source for Table 2 and Fig. 5
  protocol-thermal-bench.md   the hardware protocol for Appendix A.4, not yet run
```

Everything is simulation. There are no hardware measurements in this repository,
and §8 of the manuscript says so.

## Reproducing a result

The scripts take the rollout directory from `ROLLOUT_ROOT`, so the archive is
self-contained:

```bash
cd data/scripts
ROLLOUT_ROOT=../rollouts python analyze_command_spectrum.py /tmp/out   # Table 2, Fig. 5
python e1_sim_rho_sweep.py   /tmp/out                                  # Fig. 3
python e1b_sim_load_sweep.py /tmp/out                                  # §5.1, the crossover
ROLLOUT_ROOT=../rollouts python e3_command_filters.py /tmp/out         # Table 3, open loop
```

`analyze_command_spectrum.py`, `e1_sim_rho_sweep.py` and `e1b_sim_load_sweep.py`
need only NumPy. They run in seconds on a laptop and reproduce Table 2 and the
crossover exactly.

The two closed-loop experiments need a GPU, MuJoCo Playground and a trained
checkpoint:

```bash
python e4_closed_loop.py    --params <run>/params.pkl --out /tmp/out --tag baseline
python e5_torque_spectrum.py --params <run>/params.pkl --out /tmp/out --tag baseline
```

**Checkpoints are not in this repository.** Each `params.pkl` is 1.7 MB and there
are seven of them; they are training artefacts, not evidence. The rollouts they
produced are here instead, and those are what every table is computed from. To
regenerate the checkpoints, run the reward ablation described in §4 at 60M
timesteps per variant, about 6.6 minutes each on an RTX 5080.

## What each file is

### scripts/

| File | Produces | Needs |
|---|---|---|
| `derive_g1_gains.py` | §2, the 0.5·effort-limit transient and the 2.68 Hz pole | nothing |
| `analyze_command_spectrum.py` | **Table 2**, Fig. 5 | rollouts |
| `e1_sim_rho_sweep.py` | Fig. 3, the closed form and its 0.45% residual | NumPy |
| `e1b_sim_load_sweep.py` | **§5.1**, the load sweep and the 3.2 N·m crossover | NumPy |
| `e3_command_filters.py` | **Table 3**, open-loop filtering | rollouts |
| `e4_closed_loop.py` | **Table 4**, closed-loop filtering, both policies | GPU, checkpoint |
| `e5_torque_spectrum.py` | **§5.4**, the four-band heat budget | GPU, checkpoint |
| `analyze_e4.py` | aggregates E4 into per-scheme means and Cliff's delta | results |
| `plot_e1.py`, `plot_e3.py`, `plot_spectrum.py`, `plot_schematics.py` | the `pic/` figures | matplotlib |

### results/

| File | Behind |
|---|---|
| `command-spectrum.csv` | Table 2, all seven variants |
| `e1-rho-sweep.csv`, `e1-rho-sweep-config.json` | Fig. 3 |
| `e1b-load-sweep.csv` | §5.1 load sweep |
| `e3-command-filters.csv` | Table 3 |
| `e4-closed-loop-{baseline,no_torques_energy}.json` | Table 4, per-episode raw |
| `e4-summary-{baseline,no_torques_energy}.csv` | Table 4, aggregated, with effect sizes |
| `e5-torque-bands-{baseline,no_torques_energy}.json` | §5.4 band budget |
| `ablation-summary-seed0.csv` | training outcome per variant, seed 0 |
| `ablation-<variant>-metrics.csv` | the training curve for each variant |
| `g1-gain-derivation.log` | §2 |

Floats in the two large E4 JSONs are stored to six significant digits. The
aggregates recompute bit-identically from them.

### rollouts/

Seven directories, one per reward ablation variant, each holding the 400-step
(8 s) rollout its checkpoint produced at 50 Hz. `actions` is the array every
command-side statistic is computed from.

These close the Appendix C item that read *"the source rollouts are not in this
repository"*. Table 2 regenerates from them exactly.

## Provenance and honesty notes

- Every number in the manuscript traces to a file here. If a claim has no file,
  it is marked `pending` in Appendix C rather than estimated.
- The reward-ablation statistics were single-seed when first reported. Appendix
  A.2 covers the multi-seed repeat; see `results/ablation-multiseed-*.csv` if
  present.
- `e3_command_filters.py` is open-loop replay. Its conclusions were superseded by
  the closed-loop experiment; it is kept because the gap between the two is
  itself a result, reported in §5.5.
